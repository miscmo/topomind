## 2. 产品目标

学习统计功能的目标不是只展示一个计时器，而是逐步形成一套完整、可信、可扩展的学习分析体系。

### 2.1 当前确认的统计口径

- 只要用户在应用内发生操作，就判定为“正在学习”
- 停止记录学习有且仅有两种情况：
- 窗口失去焦点
- 用户在应用内无操作超过 3 分钟

### 2.2 最终形态

学习统计采用“两层入口 + 一个完整中心页”的结构：

- `悬停标题栏按钮`：显示轻量级快速预览浮窗
- `点击标题栏按钮`：打开类似设置页/统计页的全屏学习统计中心

### 2.3 设计原则

- 快速预览只回答“现在和最近怎么样”
- 全屏页面负责完整统计和明细分析
- UI 展示必须建立在可信的底层统计能力之上
- 先做统计准确，再做分析丰富
- 先做可持续演进的数据结构，再做复杂可视化

### 5.1 快速预览浮窗

定位：鼠标悬停时的快速扫读，不承载复杂交互。

- 今日学习时长

- 不做深层明细滚动区

- 不做大量图表切换

### 5.2 全屏统计中心

定位：完整学习统计主页面。

核心目标：

- 回答今天学了多久
- 回答最近是否稳定学习

- 回答某一天的学习细节是什么
- 回答学习主要集中在哪些时间段和内容上下文

## 7. 统计模型设计

## 7.1 事实数据与派生数据分层

后续统计能力建议明确分为两层：

- `事实数据`
- session
- daily record

- `派生数据`
- summary
- streak
- range analytics
- trend
- peak hours

原则：

- 事实数据可回放、可重算
- 派生数据随规则调整可重新生成
- 不依赖某一次 flush 的偶然执行结果

## 7.2 Session 定义

一个 session 的定义：

- 用户在窗口聚焦状态下
- 在应用内持续有操作
- 相邻操作间隔未超过 3 分钟

建议 session 字段：

```ts
interface LearningSession {
  id: string
  startTime: number
  endTime: number
  duration: number
  context?: SessionContext
}
```

## 7.3 Daily Record 定义

```ts
interface DailyRecord {
  date: string
  totalDuration: number
  sessions: LearningSession[]
}
```

## 7.4 Summary 定义

Summary 不应作为唯一真实来源，而应视为派生缓存：

```ts
interface LearningSummary {
  totalDuration: number
  currentStreak: number
  longestStreak: number
  lastActiveDate: string
}
```

## 8. 需要补齐的底层能力

这些内容属于后续实现必须补齐的“统计能力底座”。

### 8.1 Streak 必须基于事实日数据推导

- streak 只应基于 `daily.totalDuration > 0`
- 不应依赖某次 flush 是否恰好触发

### 8.2 跨天 session 切分

当前需要继续优化为：

- 若 session 跨过午夜
- 自动按日期拆分到前一天和后一天
- 不因为跨天而丢失连续学习记录

### 8.3 todayDuration 的稳定派生

建议长期改为：

- 已落盘日时长
- 加上当前未落盘 session 的实时增量

而不是仅依赖反复写盘同步。

### 8.4 串行化 flush 继续保留

必须保证以下写入互不重入：

- 定时 flush
- 失焦 flush
- 卸载 flush
- 工作区切换 flush
- 应用退出 flush

### 8.5 支持可扩展上下文标签

在不改变“应用内操作即学习”的口径下，增加上下文字段：

- 当前页面类型：home / kb / graph / document / monitor / statistics / setup
- 当前知识库路径
- 当前 tab 类型
- 当前文档 ID

这些字段先用于埋点和记录，不强制立即在 UI 中全部消费。

## 9. 如何更好地统计学习情况

除了基础时长，建议从 4 个维度建设学习统计能力。

### 9.1 时间量

- 今日时长
- 本周累计
- 本月累计
- 总累计
- 范围累计
- 平均每日时长

### 9.2 持续性

- 当前连续天数
- 最长连续天数
- 最近 7 天活跃天数
- 最近 30 天活跃天数
- 达标天数

### 9.3 节奏质量

- session 次数
- 平均单次 session 时长
- 最长单次 session
- 最活跃时段
- 最活跃星期几

### 9.4 上下文分布

- 哪个知识库最常学习
- 哪类页面最常活跃
- 哪篇文档停留最久
- 最近学习重心变化
- 支持按页面类型 / 知识库等上下文筛选当前统计范围
- 筛选后热力图、趋势图、目标分析和右侧结果区保持联动

## 14. 风险与注意事项

### 14.1 风险

- 若直接扩写 UI 而不继续整理底层统计模型，全屏页越丰富，错误越容易暴露
- 若 hover 预览继续堆功能，最终会和全屏页职责重叠
- 若未来增加上下文统计但不提前预留字段，会导致再次改动 session 数据结构

### 14.2 注意事项

- 快速预览和全屏统计中心必须严格分层
- 全屏统计页优先复用现有 learning-tracker 能力，不要重新发明一套状态
- 统计口径如有变化，必须先更新本文档，再改实现
