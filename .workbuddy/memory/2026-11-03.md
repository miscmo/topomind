## 修复：代码块语言下拉滚动穿透到编辑器

**现象**：代码块工具栏的语言下拉里滚轮滚到列表首尾后继续滚，整个编辑器正文跟着滚。

**根因**：`.tm-code-toolbar__menu-list`（`max-height:266px; overflow-y:auto`）是滚动容器但没有
`overscroll-behavior`，浏览器把剩余的滚动量**链式传递**给祖先滚动容器 `.tm-smart-editor-scroll`。
同类缺陷还有 `.tm-smart-block-menu`（快捷块菜单，420px + overflow-y:auto）。

**修法**：两个滚动容器各加一行 `overscroll-behavior: contain`。
（编辑器正文是原生 `overflow-y:auto` 滚动，不是 JS wheel 驱动，所以 CSS 就能拦住；
若哪天改成 JS 驱动滚动，这招会失效，需要再加 wheel 边界判断。）

**通用规则**：以后凡是「弹层/菜单/下拉内部可滚动」的容器，写 `overflow-y:auto` 时
必须同时写 `overscroll-behavior: contain`，否则滚到边界就会带着背后的内容一起滚。

**注意**：BlockNote 原生的代码块头部（含 `<select>`）已被
`SmartDocumentEditor.css:428` 用 `display:none !important` 整块隐藏，
出问题的永远是自定义工具栏 `.tm-code-toolbar`，别去给那个死 `<select>` 加样式。

## 修复：编辑行内公式时输入框自己消失 / 后续内容写错位置（偶发丢内容）

**根因链（实测确认，非猜测）**：
`blockLastModifiedExtension` 在停止输入 ~1s 后用 `setNodeMarkup` 把 `lastModified` 写回
**blockContent 节点** → ProseMirror 重建块内容节点的视图 → 行内公式的 React nodeView 被重建
→ `InlineMathRenderer` 的 `isEditing`/`draft` 全丢 → 输入框消失、焦点掉回正文，
选区还停在「点公式之前的位置」（常是块首）→ 用户继续敲字就写进错误位置，看起来像内容消失。

对照组实验：把该 extension 去掉后，编辑停顿多久输入框都在；加回来必然在 ~1s 后消失。

**修法（三处配合）**
1. `mathEditSession.ts`（新增）：`beginMathEditing/endMathEditing/isMathEditing` 计数信号。
   `blockLastModifiedExtension.flush()` 里 `isMathEditing()` 为真就推迟写入（上限 30s 兜底，防止编辑会话异常导致时间戳永不落盘）。
2. `mathSupport.tsx`：行内公式改为**本地 draft，Enter/blur/Esc 时才一次性 `updateInlineContent`**；
   编辑期间不产生 docChanged → pending 为空 → flush 根本不会来打扰。块级公式也挂上编辑信号。
3. 点击 chip 用 `onMouseDownCapture` + `preventDefault` + `stopPropagation`：
   **必须在捕获阶段拦**，冒泡阶段 React 拿到事件时 PM 已经处理完点击（改写选区→触发视图重建→编辑态立刻丢）。
   附带 `placeCursorAfterMath()`：用 `view.posAtDOM(dom,0)` 定位并把光标放到公式之后（否则提交后 `editor.focus()` 恢复旧选区）。

**顺带修的**：`SelectionMathButton` 加两道守卫 —— ① 只认 `TextSelection`（NodeSelection 范围是整个块容器，replaceWith 会把整块换成公式）；② 插入后显式把光标放到 `insertAt + 1`（`replaceWith` 只是映射原选区，映射结果仍覆盖刚插入的公式节点，继续打字会把公式替换掉）。

**通用规则**：任何「编辑器里的 React 自定义节点持有编辑态 state」都要假设**节点视图会被外部 transaction 重建**，
state 会丢。三条防线：① 编辑期间别产生文档变更；② 让会改文档的延迟任务知道「正在编辑」；③ 点击时用捕获阶段拦住 PM。
另外：不要指望 `editor.focus()` 会把光标放回「用户以为的地方」——它恢复的是停在那儿的旧选区，必要时先显式设选区。

## 修复：滚动编辑器时整个界面上移、底部露白（偶发「整页漂移」）

**现象**：编辑器正文里滚轮向下滚动，有概率整个界面（图谱 + 右栏 + 编辑器状态栏）
整体上移一段、底部露出空白，多次后内容漂出窗口，且滚不回来。

**根因（实证复现）**：目录联动（scroll-spy）对当前标题调用
`element.scrollIntoView()`（DocumentWorkspaceLayout 目录列表自动滚动）——
它会沿祖先链滚动**每一个**可滚容器。右栏外壳 / 图谱页 / 内容区都是 `overflow:hidden`，
**hidden 仍然是滚动容器**，可被程序化滚动。一旦目录项落在某外壳视口之外
（目录被拖到下方、窗口较小），该外壳就被滚动 → 整块内容上移 + 底部露白，
而 hidden 容器不接受用户滚动 → 再也滚不回来。实测单次调用即把右栏外壳滚 259px。
「偶发」= 目录项是否恰好在其外壳视口之外。

**关键事实（实验测定，别再猜）**
- **wheel 滚动链不会**带动 `overflow:hidden` 的祖先（Chrome 行为，实测即使祖先有
  滚动空间也不动）。只有**程序化滚动**会：scrollIntoView / focus / 滚动锚定。
- `overflow: clip` ≠ hidden：clip **不创建滚动容器** → 无法被滚动链、程序化滚动、
  scroll anchoring 带动。这是「只做裁剪的外壳」的正确取值。
- Tailwind v3.4 有 `overflow-clip` 工具类（已验证生成 `overflow-y: clip`）。

**修法**
1. 新增 `scrollChildIntoView(container, child)`（smartDocumentUtils）：只调目标容器
   自身 scrollTop，**绝不碰祖先链**。替换三处 scrollIntoView（目录联动、
   侧栏重命名输入框、TOC 点击兜底 → 兜底改为不动）。侧栏聚焦加 `preventScroll: true`。
2. 只做裁剪的外壳一律改 `overflow:clip`：`#root`(base.css)、App 内容区、
   `#graph-page`、`#graph-panel`、RightPanelShell。
3. 编辑器正文 `.tm-smart-editor-scroll` 加 `overscroll-behavior:contain`；
   html/body 加 `overscroll-behavior:none`。
4. `core/viewportScrollGuard.ts`（App 挂载）：根层被滚动立即复位，DEV 下打印证据
   ——既是最后一道保险，也是下次复现时的取证点。

**通用规则**：**永远不要用 `scrollIntoView`**，一律用 `scrollChildIntoView(容器, 子元素)`；
`focus()` 默认也会滚祖先，视情况加 `{ preventScroll: true }`。
新增「只裁剪」的布局外壳时写 `overflow-clip` 而不是 `overflow-hidden`。

**回归脚本联动**：`scripts/verify-critical-regressions.mts` 里有断言直指
`input?.scrollIntoView({ block: 'nearest' })`，改这类代码必须同步改断言（已改为
断言 `scrollChildIntoView(container, input)` + `preventScroll`，并反向断言禁止 scrollIntoView）。

**排查经验（Electron 无法热更新时）**：用户机器上跑的 Electron 若是生产构建
（未连 dev server，TCP 上看 renderer 与 5173 无连接），源码改动/HMR **到不了**它，
注入审计无效。且 renderer 里 `fetch`/`new Image()` 出网会走系统代理（`http_proxy`），
打本地收集端口会被拦（实测 reqfail）。想拿运行时数据，现实的通道是
`window.electronAPI.invoke('log:write'|'fs:writeAppConfig', ...)`（IPC 不走代理），
或干脆请用户在 DevTools Console 里跑脚本贴结果。

**验证手段（可复用）**：dev server（`npm run dev`，localhost:5173）能在纯浏览器里跑起来，
用 puppeteer 打开 + 临时 lab 页面（`.tmp-math-lab.html` + `src/.tmp-math-lab.tsx`，
挂载真实 `smartDocumentSchema` + 各 extension，把 editor 挂到 `window.__lab`），
就能对编辑器做程序化操作并读回文档 JSON 做断言。比 GUI 手点可靠得多，用完记得删。
lab 两个易踩点：① `BlockNoteView` 来自 **`@blocknote/mantine`**（不是 `@blocknote/react`）；
② 字典要合并 `multi_column`（见 xl-multi-column 坑），否则编辑器整体不渲染。
测侧栏块菜单：先 `mouse.move` 到块左侧槽（块 x - 20）再点
`[data-smart-document-side-menu] button`；文档插入后坐标会变，**每次都要重新取**。

## 块菜单「插入块」：上/下合并为一个入口
- 父菜单行 = `插入块` + 右侧 hint（`上方`/`下方` + `›`）；子菜单**顶部**放
  `SegmentedControl(size='sm')`（上方/下方），下面是块类型列表。一个入口覆盖两个方向。
- 方向记在**模块级变量** `lastInsertPlacement`（默认 after）：菜单每次打开都重新挂载，
  只存组件 state 会丢，导致连续在上方插入时要反复切。不落盘。
- 子菜单头部的非 Menu.Item 控件要 `stopPropagation`（click + keydown）：否则
  Mantine 可能把切换当成选中项关掉菜单、方向键会跑去移动下面列表的高亮。
- API：`editor.insertBlocks(blocks, refBlock, 'before' | 'after')`，core 默认就是
  `'before'`；首块用 before 也正常（成为新首块）。
